【任务】

请根据当前目录中提供的 需求说明 和 Reference Code，生成一个可以
实际运行的 Python Agent 项目。

必须立即使用本地工具读取以下两个输入文件并开始生成代码，不要只回复工作计划：

- `_codex_inputs/specification.txt`：完整的 需求说明，是 Agent 业务语义的唯一权威来源。
- `_codex_inputs/reference_code.py`：为 需求中所指定的功能 提供的 Python 参考实现。

不得修改这两个输入文件。生成后的 Agent 不得在运行时读取或依赖
`_codex_inputs`。

【生成结果】

当前工作目录就是最终 Agent 的根目录，不要创建额外的外层项目目录。

项目可以只有一个 Python 文件，也可以包含多个文件，但根目录必须包含 `main.py`，
并提供以下无参数入口：

def main():
    ...

`main()` 应初始化 Agent、执行需求描述的入口过程，并返回最终执行结果。

`main.py` 被 import 时不得自动运行，同时必须支持直接运行：

if __name__ == "__main__":
    main()

项目内部如何划分文件、保存变量和组织流程，由你自行决定。

【终端交互】

生成的 Agent 与用户之间的所有交互必须在终端中完成：

- 使用标准输出向用户展示提示、说明和结果。
- 使用标准输入读取用户回答。
- 不得生成 GUI、Web 页面或后台服务。
- 每次执行需求中规定的一次提问，只读取一次用户输入。
- 如果一次提问 需要获得多个字段，应从这一次用户输入中理解并提取，
  不得擅自拆成多轮提问。
- 只有当 需求规定再次执行该提问 时，才可以再次读取输入。

【需求实现】

必须完整实现需求说明表达的数据要求、初始值、操作、条件、职责协作、输入输出和控制流程。

不得使用固定示例值、占位返回值或与当前需求 绑定的测试答案替代真实功能。

【RISEN 需求的理解】

需求说明采用 Role、Input、Steps、Expectation、Narrowing 五个栏目组织业务内容。
这些栏目是需求的组织方式，不是 Agent 运行时依次执行的五个阶段。

- Input 说明任务涉及的输入及数据要求，不表示所有输入在开始时已经提供，
  也不要求在开始时一次性收集所有输入或所有分支的材料。输入的实际收集时机、
  顺序、次数和适用分支，必须遵循 Steps 中的具体要求。
- Steps 中被描述为供其他过程调用的 Worker 或子过程，其正文说明被调用时应做什么。
  Agent 从需求指定的入口开始，依照需求中的调用关系和条件执行这些过程；
  不得仅因多个过程的说明依次出现，就依次执行所有过程。

以上说明只解释需求的组织方式。具体业务目标、数据、条件、调用关系和执行顺序，
仍以 `_codex_inputs/specification.txt` 的内容为唯一依据，不得自行增加或改写。

【Reference Code】

Reference Code 为需求中对应的功能提供参考实现。

对于 Reference Code 中与语言模型调用有关的代码，可以根据本实验统一的
OpenAI Client、模型、Base URL 和 reasoning effort 配置进行替换，不要求复制其
LLM 客户端初始化和模型调用样板代码。

除上述 LLM 调用基础设施外，应尽可能妥善利用 Reference Code 已提供的内容，
包括 Prompt 内容和指令约束、输入数据的组织与序列化方式、调用前的数据处理、
输出提取与解析、清洗和类型转换、返回值构造、结果校验、空结果处理、错误处理，
以及不依赖 LLM 的确定性业务逻辑。

可以直接复用、封装、内联或进行必要适配，不限制生成项目的代码组织形式，但
不得无故丢弃 Reference Code 中已有的重要 Prompt、处理逻辑和行为约束。

如果 Reference Code 与 需求说明 的类型、接口或业务语义存在冲突，以
需求说明 为最终依据，并进行必要适配。

【运行时语言模型】

当 需求中的操作或条件 涉及自然语言理解、自然语言生成、语义转换或语义
判断时，应使用运行时语言模型完成，不得擅自替换成关键词匹配、简单正则表达式、
固定模板或硬编码结论。

明确且不需要语义理解的计算、赋值、比较、流程控制和数据处理，可以直接使用
Python 实现。

具体哪些操作和条件 需要语言模型，以及如何组织相关代码，由你根据
需求的真实语义决定。

运行时语言模型必须：

- 使用官方 OpenAI Python Client：`from openai import OpenAI`。
- 从 `.env` 或当前进程环境变量读取 `OPENAI_API_KEY`。
- 从 `.env` 或当前进程环境变量读取 `BASE_URL`。
- 优先从 `.env` 或当前进程环境变量读取 `CNLP_REFERENCE_LLM_MODEL` 作为模型
  名称；若未设置，则读取 `OPENAI_MODEL`。若两者均未设置，应报告明确错误。
- 所有运行时语言模型调用都必须显式使用 `high` reasoning effort，例如
  `reasoning={"effort": "high"}`。
- 不得在代码中写入真实 API Key 或其他凭据。

这些是生成后 Agent 的运行时模型配置，不是当前 Codex 生成代码时使用的配置。
