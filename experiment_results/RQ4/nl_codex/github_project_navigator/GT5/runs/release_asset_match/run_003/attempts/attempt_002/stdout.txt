Project Overview
## sharkdp/bat

**bat** is a Rust command-line utility described as a `cat(1)` clone “with wings.” Its purpose is to display files and standard input in a more readable terminal format while remaining usable as a drop-in replacement for POSIX `cat`.

### Core capabilities
- Syntax highlighting for many programming and markup languages, with automatic or explicitly selected language detection.
- Git integration that displays modifications relative to the Git index.
- Optional line numbers, file headers, grids, change markers, whitespace/non-printable-character highlighting, wrapping controls, and configurable themes.
- Automatic paging for interactive output, with plain file-content output when redirected or piped in non-interactive contexts.
- Reading one or multiple files, combining files and standard input, and use as a component in pipelines.
- Custom syntax definitions, themes, file-type mappings, configuration files, shell completions, and selectable pagers.

### Typical use cases and intended users
The project is intended primarily for developers, system administrators, and terminal-oriented users who want to inspect source code, configuration, logs, documentation, or command output. Examples in the README include previewing files through `fzf`, `find`, or `fd`; colorizing `git`, `man`, and command-help output; monitoring logs with `tail -f`; and viewing historical files or diffs. It can also be used wherever ordinary `cat`-style concatenation is needed.

### Technology and entry points
The primary language is **Rust**. The main execution entry point is the installed `bat` executable, invoked for example with `bat README.md`, `bat src/*.rs`, or `curl ... | bat`. The README documents installation through distribution packages (`apt`, `apk`, `pacman`, `dnf`, `emerge`, `pkg`, `pkg_add`, `zypper`), Nix, Homebrew, MacPorts, Windows package managers, and prebuilt release binaries. From source, it requires Rust 1.79.0 or newer and can be installed with `cargo install --locked bat` or `cargo install --path . --locked`. Development commands include `cargo build --bins` and `cargo test`.

### Important README limitations and caveats
- Automatic syntax detection for standard input works only when the syntax can be inferred from the first line, commonly from a shebang; otherwise use `-l`/`--language`.
- Interactive output is normally decorated and paged, whereas redirected or piped output falls back to plain contents. Integrations such as `tail -f` generally require `--paging=never`.
- UTF-8 and UTF-16 are supported natively; other encodings may need conversion, such as with `iconv`.
- Input containing ANSI escape sequences or control characters can produce garbled highlighting or wrapping. The README documents stripping/sanitizing options and alternatives that disable color and wrapping.
- Most themes are best with 24-bit truecolor terminals; restricted-color terminals may need the supplied 8-bit themes.
- The README says the bundled Manpage syntax still needs work, and custom themes currently require `.tmTheme` files rather than newer `.sublime-color-scheme` files.
- Older Debian/Ubuntu packages may install the executable as `batcat` because of a package-name conflict. Windows users need the Visual C++ Redistributable, and native Windows `bat` does not directly handle Cygwin-style `/cygdrive/*` paths without a wrapper.
- The README notes that installing from Cargo does not automatically install additional files such as the man page or shell-completion files.
