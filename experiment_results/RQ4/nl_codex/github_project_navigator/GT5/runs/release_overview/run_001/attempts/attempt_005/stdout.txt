Project Overview
## bat

**bat** is a Rust-based command-line utility from `sharkdp/bat` that serves as an enhanced `cat(1)` replacement. It displays files in the terminal with syntax highlighting, line numbers, file headers, Git modification markers, optional non-printable-character highlighting, and automatic paging for output that exceeds one screen.

### Core capabilities

- Syntax highlighting for many programming, markup, configuration, and other text languages.
- Git integration that shows modifications relative to the index.
- Automatic syntax detection for files and some standard input, with an option to specify the language explicitly.
- Paging through `less`, a built-in pager, or another configured pager.
- Plain-output and non-interactive behavior suitable for pipelines and file concatenation.
- Configurable themes, output decorations, line ranges, tab expansion, file-type mappings, and configuration files.
- Support for displaying multiple files, reading from standard input, and combining with tools such as `fzf`, `find`, `fd`, `ripgrep`, `tail`, `git`, `man`, and `xclip`.
- Shell completion generation and support for custom Sublime Text syntax definitions and themes.

### Typical use cases

Users commonly run `bat README.md` or `bat src/*.rs` to inspect source files interactively, use it as a syntax-aware previewer for `fzf` and file searches, view Git output with highlighting, inspect logs, colorize manual pages and command help, or use it in pipelines where it falls back to plain file contents. It can also be configured as a more readable interactive replacement for `cat`, although paging and terminal decorations may need to be disabled when exact `cat`-style behavior is required.

### Intended users

The project is intended for developers, system administrators, and terminal users who regularly inspect source code, configuration files, logs, documentation, or command output from a shell. It is also useful to developers integrating a terminal file previewer into scripts and command-line workflows.

### Technology and entry points

The primary technology is Rust. The main executable is `bat`, with command-line usage documented through `bat --help`. Users can install it through common operating-system package managers, Homebrew, MacPorts, Nix, Snap alternatives are not officially recommended, Windows package managers, prebuilt release binaries, or Cargo. Building from source requires Rust 1.79.0 or newer; the documented commands are `cargo install --path . --locked` for a local checkout and `cargo install --locked bat` from crates.io. Development uses `cargo build --bins` and `cargo test`, with a recursive Git clone recommended to retrieve submodules.

### Important limitations and caveats

- UTF-8 and UTF-16 are supported natively; other encodings may need to be converted to UTF-8 first, for example with `iconv`.
- ANSI escape sequences and other control characters can interfere with highlighting, wrapping, and output rendering. The README recommends `--strip-ansi`, `--sanitize`, or disabling color and wrapping for problematic or untrusted input.
- Automatic language detection from standard input is limited; it generally needs information such as a shebang on the first line, or the language must be supplied with `-l`.
- Accurate colors depend on terminal capabilities. Truecolor support and the `COLORTERM` environment variable affect rendering, while restricted terminals may require one of the 8-bit themes.
- Older Debian and Ubuntu packages may install the executable as `batcat` because of a package-name conflict.
- Native Windows use may require the Visual C++ Redistributable and a more capable pager such as `less`; Cygwin Unix-style paths are not handled natively without a wrapper.
- Custom themes currently must use `.tmTheme` files; newer `.sublime-color-scheme` files are not supported.
- The README notes that the repository's Manpage syntax still needs work, and it directs users to an external project for some help-message syntax issues.
- No officially supported Snap package is recommended.
