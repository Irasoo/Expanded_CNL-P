Project Overview
## bat — a cat clone with wings

**bat** is a command-line replacement for the traditional POSIX `cat` utility. Its primary purpose is to display and concatenate files while adding syntax highlighting, line numbers, Git change markers, file headers, paging, and other terminal-oriented presentation features. It is designed to remain useful as a normal `cat`-style tool: when output is redirected or piped, it falls back to plain file contents.

### Core capabilities

- Syntax highlighting for many programming and markup languages.
- Automatic or explicitly selected language detection for files and standard input.
- Git integration that displays modifications relative to the Git index.
- Optional line numbers, file headers, grids, separators, and non-printable-character highlighting.
- Automatic paging for output that is larger than the terminal screen, using `less`, another configured pager, or bat’s built-in pager.
- File concatenation and standard-input support, including combinations such as files, `stdin`, and files in one command.
- Customizable themes, styles, syntax definitions, file-type associations, tab handling, and configuration files.
- Integration with tools such as `fzf`, `find`, `fd`, `ripgrep`, `tail`, `git`, `man`, and code-formatting wrappers.
- Optional sanitization and ANSI/control-sequence handling for problematic or untrusted input.

### Typical use cases

Users commonly invoke `bat` to:

- Inspect source code, configuration files, Markdown, logs, and other text files in a terminal.
- Preview files from `fzf`, `find`, or `fd`.
- View Git-managed files with visible added or modified lines.
- Display `git show` or `git diff` output with syntax highlighting.
- Page manual pages or colorize command help output.
- Monitor log files with `tail -f` and syntax highlighting.
- Replace interactive uses of `cat` while retaining plain output in pipelines and redirections.

Typical commands include `bat README.md`, `bat src/*.rs`, `bat -A /etc/hosts`, and `curl ... | bat`. The project also documents using `cargo install` to install it from source or crates.io.

### Intended users

The project is aimed primarily at developers, system administrators, power users, and anyone who regularly reads text or source files from a terminal. Its documented integrations also make it suitable for users who build shell-based workflows around Git, file search, interactive fuzzy finding, logs, and Unix command pipelines.

### Important README limitations and caveats

- **Terminal and color requirements:** The README recommends a terminal with 24-bit truecolor support for many themes. Restricted-color terminals may require one of the documented 8-bit themes.
- **Piped output differs from interactive output:** `bat` normally uses a pager and terminal decorations interactively, but generally emits plain file contents when output is redirected or piped. Options such as `--paging=never`, `--plain`, or forced colorization are needed for particular pipeline behaviors.
- **Automatic language detection is limited for stdin:** When reading standard input, highlighting may work only when the language can be inferred from the first line, commonly via a shebang. Otherwise, the language must be specified with `-l` or `--language`.
- **Input encoding support is not universal:** UTF-8 and UTF-16 are supported natively, but other encodings may need to be converted to UTF-8 first.
- **ANSI and control sequences can cause garbled output:** Files containing escape sequences or control characters may need ANSI stripping, sanitization, or disabled colorization and wrapping.
- **Windows and Cygwin caveats:** Windows users need the Visual C++ Redistributable. Cygwin Unix-style `/cygdrive` paths are not natively supported without a wrapper or path conversion.
- **Packaging differences:** Older Debian/Ubuntu packages may install `batcat` rather than `bat`. The README says there is no currently recommended Snap package, and existing Snap packages are not officially supported.
- **Source installation does not install everything automatically:** Installing with Cargo does not automatically install the man page or shell-completion files; these may need separate handling.
- **Customization format limitations:** Custom themes must use `.tmTheme` files; newer `.sublime-color-scheme` files are not currently supported. The README also notes that the bundled Manpage syntax still needs work.
- **External tool dependencies:** Several documented workflows depend on tools such as `less`, `fzf`, `fd`, `ripgrep`, `xclip`, `iconv`, or platform-specific package managers; these are not all part of bat itself.
