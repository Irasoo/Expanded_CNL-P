Project summary:
bat is a Rust command-line utility from the sharkdp/bat project that provides a more capable, presentation-oriented replacement for the Unix cat(1) command. Its purpose is to display and concatenate files while making terminal output easier to read. Core capabilities include syntax highlighting for many programming and markup languages, automatic or explicitly selected language detection, line numbers, file headers, grids and other output styles, Git index-change markers, paging through less or another configured pager, display of non-printable characters, configurable themes and syntax definitions, stdin support, file concatenation, shell-completion generation, and optional sanitization or stripping of terminal control sequences. Typical uses include inspecting source code and configuration files, previewing search results from tools such as fzf, fd, find, and ripgrep, viewing git show or git diff output, colorizing man pages and command help, monitoring logs with tail -f, and acting as a cat-compatible command in scripts and pipelines. It is intended primarily for developers, system administrators, terminal users, and people who want enhanced file previews or terminal-readable command output. The primary technology is Rust, with syntax highlighting based on the syntect library and Sublime Text syntax/theme formats. The main execution entry point is the installed bat executable; Debian/Ubuntu, Alpine, Arch, Fedora, Gentoo, FreeBSD, OpenBSD, openSUSE, macOS, Windows, Nix, Homebrew, MacPorts, and other package or binary distribution paths are documented. From source, Rust 1.79.0 or newer is required; typical commands are cargo install --locked bat, cargo install --path . --locked, cargo build --bins, and cargo test. The README states that the project is available under either the MIT License or Apache License 2.0 at the user's option, while the supplied repository metadata identifies Apache-2.0. The repository is not archived and the supplied data reports a recent update on 2026-09-12, indicating that it is maintained rather than discontinued; this assessment does not rely on star or issue counts. Important README limitations include the fact that syntax highlighting for stdin can only be detected from the first line, often requiring a shebang or an explicit language; UTF-8 and UTF-16 are supported natively but other encodings may need conversion; ANSI escape sequences and other control characters can produce garbled output unless stripping, sanitization, or disabled highlighting/wrapping is used; many themes work best with terminals supporting 24-bit truecolor; the bundled Manpage syntax still needs work; custom .sublime-color-scheme themes are not supported, only .tmTheme files; older Debian/Ubuntu releases may install the command as batcat; Windows requires the Visual C++ Redistributable and has limited pager considerations; and the Windows build does not natively accept Cygwin-style /cygdrive paths without a wrapper.
