`bat` is a Rust-based command-line utility from the `sharkdp/bat` repository. It is described as “a cat(1) clone with wings”: a user-friendly alternative to POSIX `cat` that displays or concatenates files while adding syntax highlighting, Git change markers, optional line numbers and file headers, visualization of non-printable characters, and automatic paging for output longer than one screen. When output is redirected to another process or file, it normally falls back to plain file contents, making it suitable for many `cat`-style pipelines.

Typical uses include viewing one or more source or markup files in a terminal, reading standard input, concatenating files, previewing search results, monitoring logs with `tail -f`, colorizing help and manual pages, and displaying content produced by tools such as Git, `fzf`, `find`, `fd`, and `ripgrep`-related utilities. Its intended users are terminal users and developers who want more readable file output or a configurable pretty-printing component. The repository also documents a Rust library API for applications that need `bat`’s pretty-printing features, although library consumers must enable either the `regex-onig` or `regex-fancy` feature.

The primary implementation language is Rust. The main execution entry point is the `bat` command, although some older Ubuntu and Debian packages install it as `batcat` because of a package-name conflict. Installation paths documented in the README include operating-system package managers on Linux, macOS, BSD, and Windows; prebuilt binaries from GitHub Releases; and source installation with Cargo. Windows requires the Visual C++ Redistributable. Building from source requires Rust 1.79.0 or newer, using `cargo install --path . --locked`; installation from crates.io uses `cargo install --locked bat`. Cargo installation does not automatically install all additional files, such as manual pages and shell completions, though completions can be generated with `bat --completion <shell>`.

Customization is available through command-line options, environment variables, and configuration files. Users can select highlighting themes and output components, configure paging, define syntax mappings, and add Sublime Text `.sublime-syntax` definitions or `.tmTheme` themes. Newer `.sublime-color-scheme` theme files are not supported. The tool supports UTF-8 and UTF-16 natively; other encodings may need conversion to UTF-8. Syntax detection from standard input can be limited when the language cannot be identified from the first line, so users may need to specify a language explicitly.

Important operational limitations in the README include dependence on terminal capabilities for optimal color rendering, with 24-bit truecolor recommended unless an included 8-bit theme is used. ANSI escape sequences and control characters in input can interfere with highlighting and wrapping, although stripping and sanitization options are documented. Paging must be disabled for continuously streamed input such as `tail -f`. On Windows, paging may require a separate `less` installation; native Windows builds do not directly accept Cygwin-style absolute paths without a wrapper. The README does not recommend Snap packages because available packages are not officially supported. The bundled man-page syntax is also identified as still needing work.
