CNL-P 使用反馈草稿
研究背景
本研究中的 CNL-P 是一种被设计为产品形态的结构化 Prompt 语言：左侧为 CNL-P 表单，右侧为自然语言聊天框；用户既可以与 AI 自由对话，也可以随时编辑左侧的 CNL-P 文本，从而调整 Agent 行为。本研究的评价对象是：非编程背景的使用者在使用该产品的过程中，会遇到哪些阻碍。

以下反馈来源于本人作为实验参与者完成 RQ1 任务的过程。我并不提出解决方案，只描述遇到的具体障碍。

核心障碍
教程罗列了大量功能模块，但作为非编程背景的使用者，我在使用过程中遇到了三类核心障碍：

想找某个功能模块时，找不到入口；
看到某些模块时，感觉功能重复，不知该用哪一个；
模块是否要用、什么时候要用、用到什么程度，完全没有判断依据。
下文按「教程、功能模块、格式与结构、使用便利性」四条线组织，每条线下列出我在写作过程中遇到的障碍。

1. 教程层面的障碍
1.1 教程按模块类别组织，不按写作过程组织
教程按模块逐个介绍：PERSONA、AUDIENCE、CONSTRAINTS、CONCEPTS、TYPES、VARIABLES、WORKER、INPUTS、OUTPUTS、EXAMPLES、MAIN_FLOW、ALTERNATIVE_FLOW、EXCEPTION_FLOW、SEQUENTIAL_BLOCK、IF、FOR、WHILE、COMMAND、CALL、INPUT、DISPLAY。

但我实际的写作顺序并不是这样。我是先写主流程的 COMMAND，写完回头补 PERSONA 和 AUDIENCE，再通读补 CONCEPTS，最后找重复抽变量。教程顺序与写作顺序不一致。

1.2 模块「使用时机」未显式提示
教程告诉我有哪些模块，但没有告诉我「在什么情况下会需要这个模块」。我作为初学者，能看懂模块定义，但不会主动调用。例如我知道 SET 是「存为变量」，但我不会想到要在第一遍写作时使用它。

1.3 没有集中入口或速查表
教程将模块说明分散在不同章节。每次写 CNL-P，我都要反复翻教程确认下一步该用哪一个。教程没有一张集中入口或速查表，能让我在写作过程中快速定位。

1.4 写作顺序与教程组织顺序错位
教程按模块类别组织：PERSONA → AUDIENCE → CONSTRAINTS → CONCEPTS → TYPES → WORKER → FLOW。我按教程顺序写，会在 CONCEPTS 和 TYPES 处卡住，因为此时我尚未写主流程，不知道哪些术语有歧义、是否需要类型。

2. 功能模块层面的障碍
2.1 功能模块数量多
教程列出二十余个模块。我每次写 CNL-P 都要反复确认该用哪一个。即使写完也不确定用得对不对。

2.2 模块功能看似重复
我作为非编程使用者，看 ALTERNATIVE_FLOW 与 IF / ELSE 时，一眼看不出它们在细节上有什么本质区别。它们在视觉上都像「包住一段命令」。我又看到案例把「目的地信息有限」放进 ALTERNATIVE_FLOW，把「目的地输入无效」放进 EXCEPTION_FLOW，直观觉得这两种情况完全可以用 IF / ELSE 表达。

这种「看似重复」的感受，源于教程没有给出两者在「执行完毕后是否返回主流程」、「是否改变整体流程拓扑」、「是否需要单独命名管理」上的对比。

2.3 Agent 与 Worker 拆分时机与变量抽取时机一致
教程把 Agent 拆 Worker、变量、SET、REF 都作为基础功能介绍。但我作为非编程使用者，第一遍写作时根本不会想到要拆 Worker，也不会想到抽变量。原因相同：没有「重复」发生，所有内容都是新的，脑子里没有「这一段我刚才写过」或「这一步可以独立出来」的体验。我是在写完全部内容回头审视时，才发现某段描述重复了、某一步可以独立，才意识到应该抽变量或拆 Worker。

我的实际体验是：产品应该在用户输出第一版 COMMAND 全部内容之后，再引导用户审视「哪些地方可以抽合成变量、Worker、REF」。如果一边写作一边进行这种抽象化处理，很可能造成功能重复或过度抽象。

2.4 EXAMPLES 写作目标不清
教程没有说明 EXAMPLES 是给 LLM 看的演示、给使用者阅读的样例，还是两者都是。也没有说明：是必须写多轮对话，还是可以只写输入 + 输出。第一次写时，我不确定写多详细才算达标。

2.5 CONCEPTS 位置不符合实际
教程把 CONCEPTS 放在写作开始的位置。但我写第一遍时，根本不会想到「这个词有歧义」。我是在写完全部内容回头通读时，才发现某处术语可能被误解。教程描述的写作顺序与我实际写作顺序相反。

2.6 TYPES 在普通任务中无可感价值
教程介绍了 DEFINE_TYPES，但没有说明「什么时候必须写」。对于饮食建议助手这种自然语言为主的普通任务，我看不出使用 TYPES 能解决什么问题。教程也没有任何提示告诉我「这类任务可以省略 TYPES」。
